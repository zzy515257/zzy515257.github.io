GAMENet: Graph Augmented MEmory Networks for Recommending Medication Combination

1.摘要

通过融合由药物图形卷积获得的记忆模块和纵向患者记录

2.介绍

以前的工作：

1.基于实例的药物推荐系统。只关注最近的诊断忽略了诊断历史，无法针对急症和慢性病做出区别判断

创新点

1.加入了纵向的病患记录作为ERH图，使用基于DDI图的药理学知识保证推荐药物的安全性

2.使用了基于后融合机制的GCN网络的嵌入多知识图谱的及以增强网络作为记忆组件，使得注意力机制能够使用纵向病患记录生成的长数组

3.模型具有安全性DDI率达到3.6%

3.相关工作

Memory Augmentde Netural Network（MANN）：使用外部记忆组件来帮助深度神经网络记住和存储事物

Graph Convolutional Network（GCN）：给定每个图节点最初附加有特征向量，每个节点的嵌入向量是其邻居的特征向量的变换加权和。所有节点同时更新，执行一层前向传播。网络越深，局部邻域越大。因此，全局信息被传播到每个图节点，以学习更好的节点嵌入。

Medication Combination Recommendation：通过纵向患者诊断记录来预测药物

3.2 数据来源与对齐

DDI 图不是从 EHR 共现统计出来的，而是来自外部知识库 TWOSIDES。构建步骤是：

  1. 从 TWOSIDES 保留 Top-40 严重程度的 DDI 类型；
  2. 把 DDI 知识库中的药物编码从 NDC 转成 ATC Third Level；
  3. 与 MIMIC-III 的药物编码对齐，得到共享药物节点集 $\mathcal C_m$；
  4. 对每一对已知有相互作用的药物 $(i,j)$，令 $\mathbf A_d[i,j]=\mathbf A_d[j,i]=1$。

所以 DDI 图刻画的是安全性约束：如果两种药在 DDI 图中相连，说明它们联合使用可能产生不良反应。

2.Dynamic Memory（DM）与 Memory Reading 构建

1. Dynamic Memory 是什么：把患者历史存成 key-value 字典

1.1 存储形式

对第 $t$ 次 visit，Dynamic Memory 记为 $M_d^t$，它存储的是该患者之前所有 visit 的信息：

其中：

  • key 是 $q^{t’}$：第 $t’$ 次 visit 时由 Dual-RNN 生成的患者表示（query）；
  • value 是 $c_m^{t’}$：第 $t’$ 次 visit 的药物 multi-hot 向量，即当时医生实际开了哪些药。

所以 DM 本质上是一个可增量插入的、向量化的字典：

  • 每看完一个 visit，就把 $(q^{t’},c_m^{t’})$ 插进去；
  • 到第 $t$ 次 visit 时，里面存的是前 $t-1$ 次 visit 的 key-value 对；
  • 当 $t=1$ 时，DM 为空。

1.2 矩阵化表示

为了做注意力计算，论文把 key 和 value 分别堆成矩阵：

  • $M_{d,k}^t$：所有历史患者表示，每行是一个 visit 的 query；
  • $M_{d,v}^t$：所有历史药物向量，每行是一个 visit 的药物 multi-hot。

1.3 这样设计的目的

论文原文是是：

“This kind of design provides a way to locate most similar patient representation over time and retrieve the proper weighted medications set.”

当当前 visit 的患者表示 $q^t$ 到来时，可以在历史中找“和当前患者状态最相似的历史 visit”，然后把这些历史 visit 对应的药物按相似度加权组合起来，作为推荐参考。

这模仿了临床中的病例检索（case-based retrieval）：医生看到当前病人，会回想“我以前见过类似病人，当时开了哪些药”。

2. Output memory representation：从两个 memory 读取输出

给定当前 query $q^t$，模型从两个 memory 读取输出：

  • 从 Memory Bank $M_b$ 读取 $o_b^t$；
  • 从 Dynamic Memory $M_d^t$ 和 Memory Bank $M_b$ 联合读取 $o_d^t$。

2.1 从 Memory Bank 读取 $o_b^t$：

含义：

  • $M_b\in\mathbb R^{|\mathcal C_m|\times d}$ 是 Memory Bank，每行是一种药物经过 EHR 图和 DDI 图 GCN 融合后的嵌入；

  • $M_b q^t$ 计算 query $q^t$ 和每种药物嵌入的相似度；

  • $M_b^{\mathrm T}$【i】【j】表示第j种药物在i次诊断中的特征

  • $o_b^t$ 是 Memory Bank 中药物嵌入的加权和，表示基于药物知识图谱，当前患者最相关的药物表示。

直观说：$o_b^t$ 回答的是“从药物知识角度看，这个患者适合哪些药”。

2.2 从 Dynamic Memory 读取 $o_d^t$：

这里分三步理解。

第一步：temporal-attention $a_s^t$

  • $M_{d,k}^t$ 是历史患者表示矩阵；

  • $M_{d,k}^t q^t$ 计算当前 query 和每个历史 visit 的相似度；

  • Softmax 后得到 $a_s^t\in\mathbb R^{|t-1|}$，表示当前患者和该患者历史记录的匹配程度。

    • 如果历史某次 visit 和当前患者很像，它的权重 $a_s^t[t’]$ 就大；
    • 如果那次 visit 开过药物 $i$，即 $c_m^{t’}[i] = 1$，它就对 $a_m^t[i]$ 贡献大；
    • 把所有相似历史 visit 的贡献加起来，就得到药物 $i$ 的“历史加权用药分数”。

    所以 $a_m^t$ 是一个历史药物分布向量：

    • 第1个元素：药物 1 在相似历史 visit 中的加权出现分数；
    • 第2个元素：药物 2 的加权出现分数；
    • ……
    • 第 $|C_m|$ 个元素：最后一种药物的加权出现分数。

这就是“temporal-attention”：在时间维度上找相似的历史 visit。

第二步：历史药物分布 $a_m^t$

  • $M_{d,v}^t$ 是历史药物 multi-hot 矩阵；

  • 用 $a_s^t$ 对历史药物做加权和，得到 $a_m^t\in\mathbb R^{|\mathcal C_m|}$，根据上面推导可知，$a_s^t$ 表示之前每次诊断与当前诊断的匹配程度，$(M_{d,v}^t)^{\mathrm T}$的【i】【j】表示第j次诊断中第i种药物是否开具。$(M_{d,v}^t)^{\mathrm T}a_s^t$所得的值为对每种药物 i，把每次历史 visit 中“是否出现药物 i”的 0/1 指示，乘以该次 visit 与当前 query 的相似度权重，再对所有历史 visit 求和。它是“历史相似病例中每种药物的加权频率”。

    • $M_{d,v}^t$ 的每一行是一次历史 visit 的药物 multi-hot 向量 $c_m^{t’}$；
    • 它的第 $i$ 个元素 $c_m^{t’}[i] \in {0,1}$ 只是“第 $t’$ 次 visit 是否开了药物 $i$”的 0/1 指示，不是连续特征向量；
    • 转置后每一列是一个历史 visit 的药物列向量 $c_m^{t’}$；
    • 与 $a_s^t$ 相乘，就是：

    即：对药物 $i$，把“每次历史 visit 是否开了它”乘以“那次 visit 与当前患者的相似度”，再全部加起来。

  • $a_m^t$ 表示根据历史相似 visit，当前患者历史上被开过哪些药、频率如何。

直观说：$a_m^t$ 是一个“历史药物分布”，它把相似历史 visit 的药物按相似度加权组合起来。

第三步：再用 $a_m^t$ 去 Memory Bank 检索 $o_d^t$
  • 用历史药物分布 $a_m^t$ 作为权重，对 Memory Bank 中的药物嵌入做加权和；
  • 得到 $o_d^t\in\mathbb R^d$。

直观说：$o_d^t$ 回答的是“结合这个患者历史上相似 visit 的用药情况，再从药物知识图谱中检索，当前应该推荐什么药”。

2.3 两个输出的区别

输出 来源 注意力 含义
$o_b^t$ 只用 Memory Bank $M_b$ content-attention $a_c^t$ 从药物知识图谱看，当前患者适合哪些药
$o_d^t$ Dynamic Memory + Memory Bank temporal-attention $a_s^t$ → 历史药物分布 $a_m^t$ → 再查 $M_b$ 结合患者历史相似病例，再从药物知识图谱检索

因为 Softmax 和加权和都是可微的，所以整个 memory reading 过程可以端到端反向传播训练。

推理时，概率大于阈值 ξ的药物进入推荐集合：

为什么是将$q^t,o_b^t,o_d^t$拼接，而不是点乘？

相乘（element-wise product）常用于：

  • 两个向量需要强交互时，如 attention 中的 query-key 匹配；
  • 维度语义对齐时，如双线性池化；
  • 需要显式建模特征交叉时。

但在 GAMENet 最后一步：

  • 三个向量来源不同，语义不对齐；
  • 输出是多标签药物，需要每个药物一个分数；
  • 拼接 + 线性层已经能表达“来源加权组合”，且更稳定。

所以论文选择拼接。

4.损失函数的设计

1. Multi-label Prediction Loss (MLL)

由于药物组合推荐可以被视为序列多标签预测问题，论文结合了两种常用的多标签损失函数：二元交叉熵损失（$\mathcal{L}_{bce}$）和多标签边际损失（$\mathcal{L}_{multi}$）。

1.1 二元交叉熵损失 (Binary Cross Entropy Loss)

用于衡量预测概率与真实标签的差异。

1.2 多标签边际损失 (Multi-label Margin Loss)

$\mathcal{L}_{multi}$ 优化目标是：使真实标签的预测概率至少比非真实标签的预测概率大 1 个 margin（间隔）。这有助于让推理阶段固定阈值（如 0.5）变得更容易。

注：$\hat{Y}_j^t$ 表示预测标签集，$L$ 为归一化项。

2. DDI Loss ($\mathcal{L}_{DDI}$)

为了控制推荐结果中的药物相互作用（DDI），设计了 DDI 损失。它利用 DDI 邻接矩阵 $\mathbf{A}_d$ 对预测结果进行惩罚。

公式说明：

  • $\hat{\mathbf{y} }_i^t \hat{\mathbf{y} }_j^t$ 给出了预测结果中药物 $i$ 和药物 $j$ 成对出现的概率。
  • $\odot$ 表示逐元素乘积。
  • 如果药物 $i$ 和药物 $j$ 组合会引起 DDI，那么 $\mathbf{A}_d[i,j] = 1$。
  • 因此，如果模型给有相互作用的药物对分配了高概率，就会产生很大的 $\mathcal{L}_{DDI}$ 惩罚。

3. Combined Loss Functions (联合损失)

在训练中，准确率和 DDI 率往往同时增加（因为真实的 EHR 数据中本身就存在 DDI）。为了得到一个准确率较高且 DDI 率较低（低于预期 DDI 率 $s$）的模型，作者受模拟退火（Simulated Annealing）启发，设计了一个动态概率切换机制。

3.1 损失函数定义

机制解析：

  • $s’$：当前批次（patient）计算出的推荐结果 DDI 率。
  • $s$：期望达到的 DDI 率。
  • 当 $s’ \le s$ 时：说明安全性达标，直接使用 $\mathcal{L}_p$ 继续优化有效性。
  • 当 $s’ > s$ 时：说明安全性超标。此时以概率 $p$ 使用 $\mathcal{L}_{DDI}$ 惩罚模型，以概率 $1-p$ 使用 $\mathcal{L}_p$。超出的越多（$s’ - s$ 越大），使用 $\mathcal{L}_{DDI}$ 的概率就越大。

3.2 温度衰减 (Temperature Decay)

  • 随着训练进行，温度 $Temp$ 会乘以衰减率 $\epsilon$ 逐渐变小。
  • 这使得概率 $p$ 在模型训练后期变得更低。目的是在模型趋于稳定时，减少随机跳变的概率，帮助模型找到有效性和安全性的最佳参数组合。
